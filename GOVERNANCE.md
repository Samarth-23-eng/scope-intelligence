# Governance

Scope Intelligence currently uses a maintainer-led governance model.

## Roles

- **Contributors** report issues, improve documentation, propose designs, and
  submit code.
- **Reviewers** are trusted contributors who consistently provide accurate,
  constructive reviews.
- **Maintainers** set release direction, merge changes, manage security
  response, and protect project quality and community standards.

Roles are earned through sustained, high-quality participation. Maintainers
may invite contributors into broader responsibilities as the community grows.

## Decisions

Routine decisions are made through issue and pull-request discussion.
Maintainers seek rough consensus, but retain final responsibility for security,
legal compliance, architecture, release scope, and ethical collection policy.

Significant changes should begin as an issue containing:

- the user problem;
- expected benefits and tradeoffs;
- data, security, privacy, and source-policy implications;
- a proposed migration and testing approach.

## Releases

Releases follow semantic versioning where practical. Breaking API or migration
changes require explicit release notes and an upgrade path.
